## 2024-05-18 - Language Switcher Toggles & i18next
**Learning:** When building custom interactive toggle groups (like language switchers), React i18next's `i18n.language` can sometimes be unreliable for computing active UI states (`aria-pressed="true"`) if the language is falling back or still initializing. Using `i18n.resolvedLanguage || i18n.language` ensures a reliable active state for accessibility. Also, simple text toggles built with `<span>` completely drop keyboard users; converting them to `<button>` with explicit `focus-visible` states makes them fully accessible without altering the visual design layout.
**Action:** Always prefer `i18n.resolvedLanguage` over `i18n.language` for calculating dynamic ARIA properties in language switchers. Convert non-interactive semantic tags (`span`/`div`) with `onClick` handlers into `<button>` elements, wrap groups with `role="group"` + `aria-label`, and hide visual separators (`/`) with `aria-hidden="true"`.
