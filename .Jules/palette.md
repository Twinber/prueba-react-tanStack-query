## 2025-04-05 - Semantic Language Switchers with dynamic active states
**Learning:** When using `react-i18next` to compute active UI states for language switchers, `i18n.language` alone might not reflect the actual rendered language immediately on load depending on the plugin setup. Relying on `i18n.resolvedLanguage || i18n.language` provides a much more robust value for setting attributes like `aria-pressed="true"`. Furthermore, implementing switchers as semantic `<button>` elements inside a `<div role="group">` significantly improves keyboard accessibility over `<span>` tags with `onClick` handlers.
**Action:** Always wrap custom multi-option toggles (like language or theme switchers) in `role="group"` with an `aria-label`, use semantic interactive tags, assign dynamic `aria-pressed` states, and prefer `i18n.resolvedLanguage` as a fallback for computing active language states.
