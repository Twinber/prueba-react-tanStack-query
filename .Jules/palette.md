## 2024-05-23 - Accessible Custom Language Toggles
**Learning:** When building custom component toggles like Language Switchers, users interacting with screen readers rely on \`role="group"\` combined with a parent \`aria-label\` to understand the grouping of options. Furthermore, using semantic \`<button>\` tags rather than \`<span>\` elements ensures out-of-the-box keyboard navigation, and the active state must be communicated via \`aria-pressed="true"\`. Decorative visual separators between elements (like "/") should explicitly use \`aria-hidden="true"\` to avoid confusing auditory announcements.
**Action:** Always replace \`onClick\` handlers on \`<span>\` or \`<div>\` elements with semantic \`<button>\` tags for interactive custom controls. Wrap related toggle elements in a \`role="group"\` container, actively manage the \`aria-pressed\` state based on current dynamic values (e.g., \`i18n.resolvedLanguage\`), and explicitly hide decorative punctuation from screen readers.
