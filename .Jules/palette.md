## 2024-04-25 - Custom Language Switcher Accessibility
**Learning:** Custom interactive elements (like the Language Switcher using `<span>` tags with `onClick` handlers) bypass native accessibility tree and keyboard navigation. Using `aria-pressed` to indicate active language state requires dynamic evaluation of `i18n.resolvedLanguage || i18n.language` to guarantee reliable state communication, as `i18n.language` may sometimes be insufficient.
**Action:** Always refactor interactive pseudo-buttons (`<span>`/`<div>` with `onClick`) to semantic `<button>` elements, wrap related options in `role="group"` with an `aria-label`, explicitly hide visual separators with `aria-hidden="true"`, and apply `focus-visible` outline styles consistent with the design system to ensure full accessibility for screen readers and keyboard users.
