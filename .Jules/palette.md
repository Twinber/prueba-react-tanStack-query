## 2025-02-18 - Language Switcher Accessibility Pattern
**Learning:** Found a common pattern where inline Language Switchers use decorative `<span>` tags with `onClick` handlers for their interactive elements, and plain text separators (like `/`). This completely fails keyboard navigation and lacks accessible labels/grouping for screen readers, while also leaving screen readers confused by the loose separator characters.
**Action:** When implementing custom stateful components with multiple distinct options (like Language Switchers): wrap them in a container with `role="group"` and an `aria-label`; use semantic `<button>` tags with `focus-visible` styles; denote the active state with dynamic ARIA attributes like `aria-pressed="true"` (leveraging the reliable fallback from `i18n.resolvedLanguage || i18n.language`); and hide visual decorative separators like `/` using `aria-hidden="true"`.
