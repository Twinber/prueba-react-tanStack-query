## 2024-05-14 - Interactive element accessibility in custom toggles
**Learning:** In React apps using Tailwind CSS, simple inline switchers (like a LanguageSwitcher) are often incorrectly implemented with non-interactive `<span>` tags and `onClick` handlers. This breaks keyboard navigation completely (elements aren't in tab order) and provides poor semantics for screen readers. Using `div` or `span` for interactive elements without proper `role` and `tabIndex` is an accessibility anti-pattern.
**Action:** When implementing custom inline toggles or switchers (such as en/es language switchers), ALWAYS use native `<button>` elements. Ensure they include explicit `aria-label`s when the visible text is just an abbreviation (e.g., "EN", "ES"), and implement robust focus indicators (`focus-visible:outline focus-visible:outline-2`) to support keyboard navigation. Decorative separators like "/" should be explicitly hidden from screen readers with `aria-hidden="true"`.
